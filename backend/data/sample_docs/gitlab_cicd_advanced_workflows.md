# GitLab CI/CD Advanced Workflows and Caching vs Artifacts Guide

Source URL: https://docs.gitlab.com/ee/ci/caching/

## Detailed Technical Comparison: Cache vs Artifacts

In GitLab CI/CD pipelines, both `cache` and `artifacts` store files generated by jobs, but they serve fundamental, distinct purposes:

| Technical Aspect | Cache (`cache:`) | Artifacts (`artifacts:`) |
| :--- | :--- | :--- |
| **Primary Purpose** | Speeding up execution of future pipeline runs by reusing project dependencies (e.g. `node_modules/`, `.venv/`, `.m2/`). | Transferring build binaries, test results, compiled assets, or reports between pipeline stages and storing for download. |
| **Persistence** | Concurrent & Persistent across pipelines and branches. Shared globally. | Temporary storage per pipeline. Downloadable via GitLab Web UI and REST API. |
| **Guaranteed Availability** | Not guaranteed. Cache can be cleared or expired at any time; jobs must fall back gracefully. | Guaranteed to exist for downstream jobs within the same pipeline run until expiration (`expire_in`). |
| **Job Dependency** | Optional. Jobs fetch cache if available, but proceed normally if missing. | Explicit. Stage 2 jobs automatically download stage 1 artifacts unless `dependencies: []` is set. |

### Caching Code Example
```yaml
cache:
  key: "$CI_COMMIT_REF_SLUG"
  paths:
    - .yarn/cache
    - node_modules/

build_job:
  script:
    - yarn install --prefer-offline
```

### Artifacts Code Example
```yaml
build_app:
  stage: build
  script:
    - npm run build
  artifacts:
    name: "production-build-$CI_COMMIT_SHA"
    paths:
      - dist/
      - build/
    expire_in: 30 days
    reports:
      junit: junit-test-results.xml
```

## Review Apps & Dynamic Environments
Review Apps dynamically provision temporary live preview environments for every feature branch or Merge Request.
- Configured via `environment: name: review/$CI_COMMIT_REF_SLUG` and `url: https://$CI_COMMIT_REF_SLUG.example.com`.
- Automatically torn down when the Merge Request is merged or closed using `on_stop: stop_review_app`.
